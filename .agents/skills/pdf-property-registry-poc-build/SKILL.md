# pdf-property-registry-poc build workflow

## Overview

Repository at `/root/dev/pdf-property-registry-poc/`. SPEC.md is the source of truth (3k+ lines, 40 sections, §36 plan with 17 phases). Use the **Opus 5 planner + Sonnet 5 implementer + Codex reviewer** model.

## Phase boundaries

Each phase: implement → `pnpm typecheck && pnpm lint && pnpm test` (all 3 exit 0) → commit `feat: phase N — <name>`. Split oversized phases but commit each sub-step.

## Critical rules (from AGENTS.md + project experience)

1. **TypeScript strict.** No `any` without comment.
2. **Lint auto-fix:** `pnpm lint --write --unsafe` (biome). Never bypass hooks.
3. **ES2025 `with { type: "json" }` fails in esbuild 0.17** — use `assert { type: "json" }`. Code adaptation documented in IMPLEMENTATION_NOTES.md.
4. **`wrangler.jsonc` is gitignored** (generated by `pnpm setup`). `pnpm build` needs `scripts/build.ts` wrapper that falls back to `wrangler.template.jsonc` on fresh clone.
5. **biome.json must ignore `public/`** (browser JS/HTML, not server TS).
6. **No real PII in committed files.** `test/fixtures/private/` is gitignored.
7. **README paths are relative** (no `~/dev/...` or `/Users/...`).

## First-deployment checklist (consolidated 2026-07-30)

When deploying this Worker for the first time on a fresh Cloudflare account, **do these in order** — each step blocks the next:

1. **Enable R2 in dashboard** — https://dash.cloudflare.com → account → R2 Object Storage → "Enable R2". Without this, `wrangler r2 bucket create` fails with error 10042.
2. **Create R2 bucket** — `npx wrangler r2 bucket create pdf-poc-files`
3. **Enable R2 public access** — `npx wrangler r2 bucket dev-url enable pdf-poc-files`. This gives you a `https://pub-....r2.dev` URL for serving page images to external services (WaveSpeed OCR). **Required** because Cloudflare WAF blocks external services from accessing Worker routes (error 1010 — see pitfalls).
4. **Set ALL secrets** (each via `npx wrangler secret put <NAME> --name pdf-property-registry-poc`):
   - `APP_API_KEY` — bearer auth for the API (generate with `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`)
   - `WAVESPEED_API_KEY` — WaveSpeed OCR provider key
   - `SOURCE_URL_SIGNING_SECRET` — HMAC secret for signed source URLs (generate same way)
5. **Verify wrangler.jsonc has ALL bindings + vars** — the code references `FILES` (R2), `EXTRACTION_WORKFLOW` (Workflow), `DB` (D1), `AI` (Workers AI). Also verify `PUBLIC_BASE_URL` matches the actual deployment URL (e.g. `https://pdf-property-registry-poc.cadeia-dominial.workers.dev`, NOT `https://pdf-property-registry-poc.workers.dev`). And `R2_PUBLIC_URL` must match the R2 dev-url from step 3.
6. **Deploy** — `npx wrangler deploy`
7. **Verify health** — `curl https://<worker-url>/api/health` should return `{"status":"ok"}`
8. **Verify auth** — `curl -H "Authorization: Bearer <APP_API_KEY>" https://<worker-url>/api/schemas` should return schema list, not `CONFIGURATION_ERROR`

**Cascading error pattern:** If you skip step 1-5 and jump to testing, you'll hit errors in sequence: first `CONFIGURATION_ERROR` (missing APP_API_KEY), then `INTERNAL_ERROR` (missing R2/Workflow bindings), then `SignedUrlError` (missing SOURCE_URL_SIGNING_SECRET), then `WaveSpeed rejected` or empty OCR (WAF blocking / wrong PUBLIC_BASE_URL). Each fix requires a redeploy. Do the checklist top-to-bottom to avoid 4+ redeploy cycles.

## Pitfalls (learned the hard way)

- **Subagent budget ~50 tool calls** before context saturates. Split phases if combined scope > 2 phases.
- **Codex is more reliable than Sonnet for setup/docs** but cannot read files as richly. Use Codex for Phases 14-17.
- **Biome ignores unknown file types** but still lints `public/`. Add `"public"` to `biome.json` `files.ignore`.
- **`parseBody` returns `string | File`** — narrow with `typeof (x as File).arrayBuffer === "function"`.
- **D1 fake needs DELETE support** — add `db.prepare("DELETE FROM ...").bind(id).run()` to `test/support/fake-d1.ts`.
- **Synthetic PDF** — minimal hand-crafted PDF blob with `%PDF-` magic is enough; don't generate a real complex one.
- **`writeFileSync` `mode` option is only honored on file *creation*** — when overwriting an existing file with looser permissions, the mode is silently ignored. **Real fix:** add `chmodSync(path, 0o600)` after the write to guarantee the mode regardless of prior state. Caught by R4 review (2026-07-30) when the original R4 fix used only `mode: 0o600` on `writeFileSync` and a regression test for overwriting an existing file exposed it. Pattern applies to any "write secrets with mode 0600" task.

## Reference files

- `references/salvage-pattern.md` — how to recover when a subagent hits the iteration cap with uncommitted code. Includes the branch dance for parallel fix dispatch.
- `references/architectural-fixes.md` — canonical fix sketches for R2/R4/R6/R9/R10 from the 2026-07-30 review. Use this when a future review cycle re-discovers the same risks.
- `references/cross-validation-report.md` — final cross-validation results (convergence checks 1-7, risk audit table, e2e/server.ts bug analysis).
- **Subagent hits iteration cap mid-task** — the subagent will leave uncommitted code in the working tree and report "not yet committed." The orchestrator must salvage: stash/list → diff → either commit directly (if small/mechanical) or dispatch a tiny continuation subagent (one or two risk IDs only) to commit + verify. See `references/salvage-pattern.md`.
- **Two parallel subagents fixing the same repo must use separate branches** — never both on `master`. If a subagent reports it committed on `master`, dispatch the next one to a fresh `review/fixes-…` branch. See `references/salvage-pattern.md` for the checkout dance.
- **Lint after EVERY commit, not just at the end** — `e2e/server.ts` (created in R1) had 2 biome errors + 1 unused-suppression warning that the R1 subagent did not catch because it ran `pnpm typecheck && pnpm test` (which don't run biome) but skipped `pnpm lint`. The lint debt was only fixed 5 commits later in a separate "chore: lint" commit by the R7 subagent. **Pattern:** every fix-commit subagent prompt must include "after each commit: `pnpm typecheck && pnpm lint && pnpm test`" — explicit `pnpm lint` step, not bundled. Biome's `useTemplate` rule on string concatenation and the `organizeImports` rule are common offenders.
- **Opus 5 refutes ~20% of risks during review** — Opus read the actual schema and found R6 ("empty `{}` proposal persisted as valid") was a false positive because the schema has top-level `required` arrays. Always have Opus verify before dispatching a "fix" — don't trust the risk register blindly.
- **R1 is the canonical P0 surprise** — `playwright.config.ts` invokes a `webServer.command` that requires a standalone boot wrapper (`e2e/server.ts`) that nobody wrote until the e2e spec was actually run. Same pattern repeats with `scripts/build.ts` for `pnpm build`. When a spec references a generated/bootstrapped file, write the bootstrapping first.
- **e2e/server.ts had TWO bugs, found in sequence** — (1) URL constructor: `tryServeStatic()` called `new URL(reqUrl)` where `reqUrl` is a relative pathname like `/api/health`; Node's `URL` constructor requires a base. Fix: `new URL(reqUrl, \`http://${HOST}:${PORT}\`)`. (2) Static handler returned `null` for path=`/`, falling through to the Hono app's JSON health route instead of serving `public/index.html`. Fix: map `/` to `index.html` explicitly. **Lesson:** when writing a Node.js HTTP server that passes requests to Hono, always test with `curl http://localhost:<port>/` AND `curl http://localhost:<port>/api/health` before wiring it into Playwright's `webServer` config. The bugs survived 9 review commits because nobody ran `pnpm test:e2e` end-to-end until the final cross-validation.
- **Node's `new URL()` vs `new URL(path, base)`** — general pattern: any code that constructs a `URL` from a request's pathname (without scheme+host) will throw `TypeError: Invalid URL`. This is distinct from `req.url` in Hono/Workers (where the runtime provides a full URL). When bridging Node `http` to a Workers-compatible handler, the pathname-only `req.url` from Node's `IncomingMessage` must be promoted to an absolute URL before any `new URL()` call.
- **In-memory DB mock must return snapshots, not live references (R10 lesson)** — `test/support/fake-d1.ts` `first()` returned the row object directly from its internal array. When a subsequent `UPDATE` mutated that same row in-place, the previously-returned reference was retroactively changed. This caused a test asserting `after3.updated_at !== after2.updated_at` to fail because both pointed to the same mutated object. **Fix:** `first()` must return `{ ...r }` (shallow copy), matching real D1 semantics where `first()` returns a snapshot. **General lesson:** any in-memory DB mock that stores rows as objects MUST deep/shallow copy on read. Otherwise, time-ordered assertions (before vs after a write) silently break. Debugging this is non-obvious because the mutation is invisible — the reference hasn't changed, only the object's fields. Symptom: `expect(x).not.toBe(y)` fails with two identical values that "should" be different because the test ran them at different times.
- **Orchestrator must run `pnpm test:e2e` at merge time, not defer to final cross-validation** — the two e2e bugs (URL constructor + static handler) survived 9 review commits because the convergence check `pnpm test:e2e` was listed but never run until Phase 4. Run it at Phase 2.5 (salvage + merge) the moment R1's commit lands.

- **WaveSpeed + API upload (no page images) → cryptic NonRetryableError** — when `PADDLE_TRANSPORT=wavespeed` and a PDF is uploaded via API (not the browser UI), `page_image_keys_json` is `"[]"`. The `parseDocumentWithPaddle` step falls through to the PDF signed URL path, but WaveSpeed only accepts images. The adapter throws `NonRetryableError: No page image URLs provided` which bubbles up as `INTERNAL_ERROR`. **Fix:** in `workflow-steps.ts:parseDocumentWithPaddle`, when WaveSpeed transport and no page images, throw a clear `INVALID_REQUEST` (400) with message: "WaveSpeed OCR requires page images. Upload via the browser UI which converts PDFs to images, or provide page images via the API." This makes the error actionable instead of cryptic. The browser UI path works because `public/app.js` converts PDF→PNG via PDF.js before upload.

- **Cloudflare Workers secrets require separate `wrangler secret put` + redeploy** — after initial `wrangler deploy`, secrets like `APP_API_KEY` and `WAVESPEED_API_KEY` must be set individually via `npx wrangler secret put <NAME> --name <worker>`. The Worker will return `CONFIGURATION_ERROR` ("Server is not configured for authenticated requests") until the secret exists AND the Worker is redeployed. `wrangler secret list` verifies. **Pattern:** deploy → set secrets → redeploy → verify with curl. Don't skip the second deploy.

- **Cloudflare dashboard permission names differ from logical names** — the token creation UI uses different labels than the API scope names. The 4 permissions needed are: `Account > Workers Scripts: Edit`, `Account > D1: Edit`, `Account > Workers R2 Storage: Edit`, `Account > Account Settings: Read`. If the user says "these permissions don't exist," walk them through the dashboard path: Profile → API Tokens → Create Token → Custom token → Permissions dropdown.

- **wrangler.jsonc must declare ALL bindings the code references** — R2 buckets (`r2_buckets`) and Workflows (`workflows`) are NOT auto-detected from source code. If the upload route calls `env.FILES.put()` or `env.EXTRACTION_WORKFLOW.create()`, the bindings MUST be in `wrangler.jsonc` or the Worker returns INTERNAL_ERROR (500) with no useful error message. **Deployment checklist:** (1) verify `r2_buckets` binding matches `FILES`, (2) verify `workflows` array has `EXTRACTION_WORKFLOW` with `class_name: ExtractionWorkflow`, (3) workflow's `d1_databases` must list `DB` binding separately, (4) run `npx wrangler deploy` → confirm output shows all bindings. **Symptom when missing:** upload returns `{"error":{"code":"INTERNAL_ERROR","message":"Internal error."}}` with empty stack trace. **Verification:** `curl -X POST /api/extractions -F 'file=@test.pdf' -F 'schemaId=property-registry-record-v1'` should return 202, not 500.

- **R2 must be enabled in Cloudflare dashboard before first use** — even with a valid API token that includes `Workers R2 Storage: Edit`, the R2 API returns error code 10042 ("Please enable R2 through the Cloudflare Dashboard") until the feature is activated. Path: Cloudflare Dashboard → your account → R2 Object Storage → click "Enable R2". Only after this can `wrangler r2 bucket create` succeed.

- **`change` event on input fields fires only on blur/Enter, not on keystroke** — if the user reports "nothing happens after typing in a field," the handler likely uses only `change`. Add a debounced `input` listener (500ms) as fallback. The `change` listener should remain for immediate response on blur/Enter. Pattern:
  ```js
  let _timer = null;
  input.addEventListener("input", () => {
    clearTimeout(_timer);
    _timer = setTimeout(() => { /* react to value */ }, 500);
  });
  ```
  This is a classic HTML gotcha — `change` = committed value (blur), `input` = every keystroke.

- **Cloudflare WAF/Bot Detection blocks external services from Worker routes (error 1010)** — when external services (WaveSpeed OCR, webhooks) need to fetch data from your Worker's internal routes (e.g. `/api/internal/source/{jobId}/pages/{pageName}`), Cloudflare's default security blocks them. The service gets HTTP 403 with error code 1010. **Solution:** serve page images directly from R2 public bucket (`https://pub-....r2.dev`) instead of through the Worker. Enable with `npx wrangler r2 bucket dev-url enable <bucket>`. Update `R2_PUBLIC_URL` in wrangler.jsonc vars. **Alternative:** add WAF custom rule to skip security for `/api/internal/source/*` path (requires custom domain on the Worker, not `workers.dev`).

- **`PUBLIC_BASE_URL` must match actual deployment domain** — common mistake: wrangler.jsonc has `https://pdf-property-registry-poc.workers.dev` but the actual URL is `https://pdf-property-registry-poc.cadeia-dominial.workers.dev`. This causes signed URLs to point to the wrong domain, and external services (WaveSpeed) get empty results because they can't fetch the images. **Symptom:** WaveSpeed processes for 34 seconds then returns empty OCR result. **Fix:** update `PUBLIC_BASE_URL` in wrangler.jsonc `vars` to match the actual deployment URL, then redeploy.

## OCR provider alternatives (updated 2026-07-30, verified)

See `references/ocr-provider-research.md` for full research + API test logs.

- **Baidu hosted** (`aistudio.paddleocr.com`) — BLOCKED. Chinese phone required.
- **WaveSpeed AI** (`wavespeed.ai/models/wavespeed-ai/paddle-ocr`) — ✅ IMPLEMENTED.
  PaddleOCR-VL-1.6 hosted, $0.01/run, OpenAI-compatible API. **Verified:**
  API key works, submit/poll contract confirmed, but `image` field does NOT
  accept PDFs (returns `Image read Error`). Solution: client-side PDF.js
  conversion in the browser. Adapter: `src/adapters/wavespeed-paddleocr.ts`
  (422 lines, multi-page concurrent orchestration).
- **Self-host** — GPU mandatory (no CPU build for VL-1.6). Two-container Docker
  architecture. $200–400/mo for GPU VPS. API contract differs from hosted version.
- **Vision LLM pivot** — single call replaces both OCR + extraction. Untested on
  complex registry documents.

### WaveSpeed adapter implementation status

- **Phase 1-2 DONE**: env vars, contracts, adapter, factory update
- **Phase 3-6 IN PROGRESS**: UI (PDF.js), workflow, tests
- Transport: `PADDLE_TRANSPORT=wavespeed` in env
- Multi-page: concurrent with limit (default 3), markdown concatenated with `---` separators
- Failed pages: annotated with `<!-- Page N: OCR failed -->` markers

### Pitfall: Research platforms thoroughly before making claims

**Initial research concluded "WaveSpeed does NOT host PaddleOCR."** This was
wrong — the model exists at `wavespeed-ai/paddle-ocr` on their platform. The
error: I searched the homepage, model catalog page, and LLM docs but didn't
search for the specific model. The homepage emphasizes media generation, and the
LLM service page doesn't list OCR models. **The model exists in a different
product surface (model inference API, not LLM service).**

**Rule:** Before making a definitive negative claim about a platform's
capabilities, search the model catalog with the specific model name. Don't rely
on the homepage description or one product section. If the user suggests a
platform, assume they know something you don't and search harder.

### Pitfall: WaveSpeed `image` field does NOT accept PDFs (verified 2026-07-30)

The WaveSpeed PaddleOCR model's input field is called `image` and described as
"Document image to parse." Despite PaddleOCR-VL being a document parsing model
that natively supports PDFs, the WaveSpeed hosted version **rejects PDFs**.

**Test result:** Submit a PDF URL → status "completed" → `outputs` contains:
```json
{"error": "Exception from the 'cv' worker: Image read Error: /tmp/...png"}
```

**Solution:** Client-side PDF→image conversion via PDF.js before upload.
The adapter (`wavespeed-paddleocr.ts`) expects `pageImageUrls: string[]`
on `OcrInput`, not a PDF URL. The browser converts PDF to PNG images
(scale 2.0), uploads them as multipart, and the Worker sends each image
URL to WaveSpeed.

**Cost implication:** 10-page PDF = 10 API calls × $0.01 = $0.10/doc
(vs $0.01 for the original PaddleOCR hosted API that accepted PDFs).

## Post-build review cycle (Opus 5 + Sonnet 5 + Codex cascade)

When the user says "use opus 5 para fazer um plano de revisão e depois despache agentes para revisar e consertar" (or equivalent), the workflow is:

### Phase 1 — Opus 5 plans (deleg_1)
Single dispatch. Read SPEC.md, IMPLEMENTATION_NOTES.md, ACCEPTANCE.md, and the top-level repo structure. Produce a 3-5 page review plan with:
- 8-12 risk items (P0/P1/P2), each with file paths, failure mode, evidence to confirm/refute
- Reviewer assignment per risk (Opus 5 / Sonnet 5 / Codex)
- Sequencing: 3-4 dispatches in parallel, final merge policy
- 5-7 measurable convergence criteria (e.g. "test suite green + Playwright runs end-to-end + no `durationMs: 0` in logs")
- Time budget

### Phase 2 — Parallel reviewer dispatches (3 in parallel, no creds)
- **Dispatch A (Opus 5)**: 5 architectural/cross-file risks. Read source, output a single memo with one section per risk, defect confirmed (YES/NO/PARTIAL), 5-30 line fix sketch, 5-15 line test sketch. Do NOT modify source.
- **Dispatch B (Codex or Sonnet 5)**: 4 mechanical/implementation fixes. Create branch `review/fixes-{IDs}`, one commit per risk with `fix: review R-N — <one-line>`. After each commit: `pnpm typecheck && pnpm lint && pnpm test` must pass.
- **Dispatch C (Codex)**: 2-3 runtime verification checks. Read-only. Try `pnpm test:e2e` and `pnpm test:live` even if they fail — capture the EXACT error. Confirm/refute risks with empirical evidence.

**Files-to-NOT-touch constraint (validated 2026-07-30 review cycle):** When dispatching two Codex subagents in parallel against the same repo (one for R2/R4/R9/R10, another for R5/R7/R8), each prompt MUST include an explicit list of files the other subagent owns. Pattern: dispatch B owns `src/services/file-validation.ts`, `src/services/upload.ts`, `test/unit/file-validation.test.ts`, `test/unit/upload.test.ts`, `scripts/smoke-test.ts`, `src/services/cleanup.ts`, `src/scheduled.ts`. Dispatch D owns everything else. Without this constraint, both subagents edit the same files concurrently and the orchestrator must resolve merge conflicts. **Each subagent must work on a separate `review/fixes-…` branch** so the orchestrator can merge sequentially with `git checkout master && git merge --no-ff review/fixes-…` per branch.

### Phase 2.5 — Salvage + merge
When dispatch B and dispatch C return, the orchestrator:
1. Check `git log` for which branch each subagent used. If B used a branch, fast-forward master or cherry-pick.
2. If B's branch and the parent repo are both dirty (rare), use `git stash` + `git checkout` + `git stash pop` to recover. **Discard via `git checkout -- <file>` if the subagent's partial work conflicts with the orchestrator's plan.**
3. Run `pnpm check` on master. If anything breaks, dispatch a tiny fix subagent.

### Phase 3 — Architectural fixes from Opus 5 memo (Dispatch D)
After A's memo lands, dispatch a second Codex subagent on a fresh `review/fixes-r2-r4-r9-r10` branch to apply the 4 architectural fixes A confirmed. **Each subagent must declare which files are off-limits to the other.** (See R2/R9/R10 canonical fix set in `references/architectural-fixes.md`.)

### Phase 4 — Cross-validation (Opus 5 final pass)
One final Opus 5 read-through of merged state against SPEC §37 acceptance checklist. Update `IMPLEMENTATION_NOTES.md` and `docs/ACCEPTANCE.md` only after all convergence criteria pass.

### Convergence criteria template (paste into Phase 1 prompt)
1. `pnpm check` exits 0 (lint + typecheck + 256 existing tests + any new regression tests)
2. `pnpm test:e2e` exits 0 (confirms R1 fixed)
3. `grep -rn "durationMs: 0" src/ scripts/` returns zero matches
4. New unit test `test/integration/workflow-replay.test.ts` exists and passes
5. New unit test asserts empty proposal cannot persist as "valid" record
6. New query test asserts any `needs_review` row has non-null `review_kind`
7. Live schema metadata reachable from `/api/schemas/property-registry-record-v1` (deferred to creds gate)

If 1-6 pass without creds, the POC is "perfect" in build-sandbox sense. Full "perfect" (SPEC §38 items 4-8) requires 7 plus the deferred cred-gated live probe.
